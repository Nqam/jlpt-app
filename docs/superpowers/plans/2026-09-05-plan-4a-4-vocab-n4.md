# Plan 4a-4 — Vocabulary Reference (N4) Implementation Plan

**Goal:** Extend the vocabulary reference with N4 — 630 hand-translated N4 word entries — reusing
Plan 4a-3's pipeline (`scripts/build-content/vocab.ts`, `vocab_points` schema, `ContentDb`
methods, `VocabListScreen`/`VocabDetailScreen`) unchanged, mirroring exactly how Plan 4a-2 added

**Architecture:** No pipeline code changes needed — `loadAllVocab` already merges every `*.tsv`
file in `content/vocab/` by filename-derived level. This plan is entirely content authoring
(`content/vocab/n4.tsv`) plus test extension for the new level.

**Spec:** `docs/superpowers/specs/2026-09-04-plan-4a-kanji-vocab-content-design.md`, descoped the
same way as Plan 4a-3 (no JMdict import, no `vocab_examples`/`vocab_kanji` tables).

**Predecessor:** Plan 4a-3 (`2026-09-05-plan-4a-3-vocab-n5.md`, merged). Its Global Constraints
(TSV format, `id` computed from headword+reading with `-N` collision suffixes, list-not-grid UI)
apply unchanged.

**Data provenance and source-quality findings (record before re-deriving):**

- Source: `en.wikibooks.org/wiki/JLPT_Guide/JLPT_N4_Vocabulary`, 10 per-kana-row table subpages
  (Row_A..Row_Wa — same 11-page structure as N5's source page, minus one: N4's own `Row_misc` is
  a **different, non-tabular bullet-list page** that partially overlaps the per-row tables in
  content — e.g. コンサート appears in both `Row_Ka`'s table and `Row_misc`'s bullet list — but
  without separate reading/kanji/POS columns. Treated as a redundant/legacy alternate listing and
  **excluded**, same as trusting a page's own structured table over an inconsistent prose section
  (kanji plans' precedent). 630 real entries after excluding one malformed 2-field orphan row
  ("~おき" with no meaning/number, confirmed not part of the numbered sequence).
- **This source's POS marking is coarser than N5's**: word-type is either blank (most verbs, many
  unmarked nouns) or one of `(名)(副)(代)(形)(接)(尾)(助)`, with `(形)` covering BOTH i-adjectives
  and na-adjectives indiscriminately (confirmed: さかん/盛ん "popular" is a na-adjective tagged
  identically to i-adjectives like こまかい). So `pos_norm` here uses "гл."/"прил." without N5's
  conjugation-class/и-на distinction — a genuine data-quality ceiling of this source, not a
  parsing shortcut.
- **A real source tagging bug found and NOT propagated**: the source's `(代)` (=pronoun) tag is
  applied to 17 entries, only 5 of which are actual pronouns (彼女/彼/彼ら/君/皆). The other 12 —
  客 "guest", 警官 "police officer", 社長 "company president", 先輩, 祖父, 祖母, 大学生, 中学校,
  妻, 店員, 泥棒, 歯医者 — are common nouns for people (and one place, 中学校 "middle school"),
  mistagged. Manually corrected to "сущ." (see `MANUAL_POS_OVERRIDES` in the data-prep script,
  archived below) since shipping a wrong grammatical-category label as-is would be actively
  incorrect learning content, not a defensible "preserve the source" call.
- **~30 additional verbs/adverbs whose English gloss doesn't start with "to "** (Wikibooks author
  inconsistency, e.g. "apologize" instead of "to apologize" for 謝る) were caught by manual review
  during translation and tagged correctly rather than left blank by the automatic
  `meaning.startsWith('to ')` heuristic. 15 entries had a genuinely blank English gloss in the
  source (not a parse bug — confirmed in the raw wikitext) and got a hand-authored Russian gloss
  directly, skipping an English intermediate (`~員`, `~会`, `~くん`, け(shitsu-note sense), けれど
  も, `~軒`, 御~, `~ございます`, こと, すく(2nd sense), すり, `~だす`, できる(2nd sense), `~まま`,
  plus あ/interjection).
- Zero (headword, reading) id collisions exist in this N4 dataset (checked programmatically) —
  unlike N5's four kana-only homographs. `parseVocabSeedFile`'s `-2`/`-3` dedup logic is simply
  inert here; it's a general safety net, not something this plan needed to exercise.

## Task 1: Author `content/vocab/n4.tsv` (630 entries)

Data-prep steps (mirrors Plan 4a-3's WIP-directory workflow, done in a scratch directory deleted
after this plan lands — see Task 3): fetch raw wikitext for the 10 table-format Row_X subpages
via `curl -A "<contact UA>" ".../action=raw"` (a bare `curl` without a User-Agent gets HTTP 429
from Wikimedia — confirmed the hard way); parse with a per-`{|...|}`-table splitter (not a
whole-file `|-`-split — a whole-file split lets one table's trailing content bleed into the next
table's header, silently corrupting the last row's meaning field per vowel-section); clean
`[[wikt:X|Y]]` links and `【...】` wrappers; derive `reading_clean`/`headword`/`pos_norm`/`id`
exactly like `vocab.ts`'s own logic (validated to agree before writing the TSV); apply the
`MANUAL_POS_OVERRIDES` correction list above; translate all 630 English glosses to Russian by
hand; merge into `content/vocab/n4.tsv`.

- [x] `content/vocab/n4.tsv` created, 630 tab-separated rows, verified: 4 fields per line, no
  stray tabs/newlines in any field, `npm run build-content` (triggered by `pretest`) produces
