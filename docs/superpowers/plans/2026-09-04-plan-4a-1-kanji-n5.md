# Plan 4a-1 — Kanji Reference (N5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a kanji reference category to the content pipeline and the app — a new `kanji_points` table in `content.db`, hand-authored N5 kanji data (readings, meanings, stroke count), and browsing screens (`/kanji`, `/kanji/:id`) replacing the current placeholder.

**Architecture:** A new content-pipeline module (`scripts/build-content/kanji.ts`) parses one TSV file per level (`content/kanji/{level}.tsv`) into `KanjiPoint[]`, validated and inserted into a new `kanji_points` table alongside the existing `grammar_*` tables — same `content.db`, same deterministic build (`npm run build-content`), no new runtime dependency and no network access required. `src/storage/content-db.ts` gains read methods mirroring the grammar ones; two new React screens mirror `GrammarListScreen`/`GrammarDetailScreen`.

**Tech Stack:** TypeScript, `sql.js` (existing), React 18, react-router-dom, Vitest, Playwright — all already in the project; **no new dependency is added by this plan**.

**Spec:** `docs/superpowers/specs/2026-09-04-plan-4a-kanji-vocab-content-design.md` §2–6 (read it — this plan argues from it, with one documented mechanism change, see below). Parent spec: `docs/superpowers/specs/2026-09-03-jlpt-desktop-app-design.md`.

**Deviation from the spec's stated mechanism (agreed with the project owner before this plan was written):** the spec describes kanji enrichment via a scripted KANJIDIC2 XML import (`scripts/fetch-dictionaries.ts` + an XML parser). This plan does **not** build that — for a set this small (81 N5 characters, ~260 with N4 later), a scripted dictionary import adds a network dependency, a new parser dependency, and a data-format layer for no real benefit over hand-authored data, which is exactly how the grammar content already works. Readings/meanings for the 81 N5 kanji are authored directly into `content/kanji/n5.tsv` in this plan (real, standard readings — not placeholders). The scripted-import mechanism is reserved for **vocabulary** (a later plan, ~800–2300 words — hand-authoring reading/part-of-speech data at that volume is impractical). If a future plan needs KANJIDIC2 after all (e.g. for N3–N1 volume), it is free to add `fetch-dictionaries.ts` then; nothing in this plan blocks it.

## Global Constraints

- **Browser-safe `src/**`:** no `electron`, `node:*`, `fs`, `path`, `child_process`, `os`, `crypto` imports anywhere under `src/**`. `npm run lint` must stay green (ESLint rule `no-restricted-imports`).
- **`scripts/**` and `tests/**`** may use Node APIs freely (`no-restricted-imports` is off there).
- **Content pipeline stays deterministic and offline.** `npm run build-content` must not touch the network. Two builds from the same inputs must produce byte-identical `content.db` (already asserted by an existing test; do not break it).
- **`content/kanji/{level}.tsv` format:** one kanji per line, 5 tab-separated fields — `char`, on'yomi readings (comma-separated, empty allowed), kun'yomi readings (comma-separated, empty allowed, `.` marks the okurigana boundary per standard dictionary notation, e.g. `まな.ぶ`), stroke count (positive integer), Russian meaning. Blank lines and lines starting with `#` are skipped. The level code is derived from the filename (`n5.tsv` → `N5`), uppercased.
- **`kanji_points.id` format:** `` `${level.toLowerCase()}-${char}` ``, e.g. `n5-学` — mirrors `grammar_points.id`'s `{level}-{slug}` shape, using the character itself as the unique slug (kanji have no natural romaji key without ambiguity).
- **UI text in Russian.** No furigana rendering needed here (kanji have no ruby text of their own in this view — readings are shown as plain text, on'yomi/kun'yomi lists).
- **`content/CREDITS.md`** (new file) records the open-license sources used for content scope, per the spec's §2 attribution requirement.
- **TDD:** failing test first. Vitest for the pipeline (`tests/scripts/`) and storage/UI layers, using the same patterns as the existing grammar tests — fixture files in temp directories for pipeline unit tests, the real built `resources/content.db` for `ContentDb` integration tests (via `pretest: npm run build-content`), fake `ContentDb`/`ContentDbContext` objects for component tests.

```ts
import { readFileSync, readdirSync } from 'node:fs';
import { join } from 'node:path';

const FIELD_COUNT = 5;

export interface KanjiPoint {
  id: string;
  level: string;
  char: string;
  onyomi: string[];
  kunyomi: string[];
  strokeCount: number;
  meaningRu: string;
}

/**
 * Один уровень — один TSV-файл content/kanji/{level}.tsv. Строка:
 * символ<TAB>он-чтения через запятую<TAB>кун-чтения через запятую<TAB>кол-во черт<TAB>русское значение
 * Пустые строки и строки, начинающиеся с "#", пропускаются.
 */
export function parseKanjiSeedFile(path: string, level: string): KanjiPoint[] {
  const out: KanjiPoint[] = [];
  const lines = readFileSync(path, 'utf8').split('\n');
  lines.forEach((raw, i) => {
    const line = raw.trim();
    if (!line || line.startsWith('#')) return;
    const fields = line.split('\t');
    if (fields.length !== FIELD_COUNT) {
      throw new Error(
        `${path}:${i + 1}: expected ${FIELD_COUNT} tab-separated fields, got ${fields.length}`,
      );
    }
    const [char, onyomiRaw, kunyomiRaw, strokeRaw, meaningRu] = fields as [
      string, string, string, string, string,
    ];
    const strokeCount = Number(strokeRaw);
    if (!Number.isInteger(strokeCount) || strokeCount < 1) {
      throw new Error(`${path}:${i + 1}: bad stroke count "${strokeRaw}" for "${char}"`);
    }
    out.push({
      id: `${level.toLowerCase()}-${char}`,
      level,
      char,
      onyomi: onyomiRaw ? onyomiRaw.split(',').map((s) => s.trim()) : [],
      kunyomi: kunyomiRaw ? kunyomiRaw.split(',').map((s) => s.trim()) : [],
      strokeCount,
      meaningRu: meaningRu.trim(),
    });
  });
  return out;
}

export function loadAllKanji(dir: string): KanjiPoint[] {
  let files: string[];
  try {
    files = readdirSync(dir).filter((f) => f.endsWith('.tsv'));
  } catch {
    return [];
  }
  const out: KanjiPoint[] = [];
  for (const file of files) {
    const level = file.replace(/\.tsv$/, '').toUpperCase();
    out.push(...parseKanjiSeedFile(join(dir, file), level));
  }
  return out;
}

export function validateKanji(points: KanjiPoint[]): string[] {
  const errors: string[] = [];
  const seen = new Set<string>();
  for (const p of points) {
    if (seen.has(p.id)) errors.push(`duplicate kanji id "${p.id}"`);
    seen.add(p.id);
    if (!p.char) errors.push(`${p.id}: empty char`);
    if (!p.meaningRu.trim()) errors.push(`${p.id}: empty meaningRu`);
    if (p.onyomi.length === 0 && p.kunyomi.length === 0) {
      errors.push(`${p.id}: no on'yomi or kun'yomi readings`);
    }
  }
  return errors;
}
```

```ts
  private rowToKanji(r: {
    id: string; level: string; char: string;
    onyomi_json: string; kunyomi_json: string; meaning_ru: string; stroke_count: number;
  }): KanjiPoint {
    return {
      id: r.id,
      level: r.level,
      char: r.char,
      onyomi: JSON.parse(r.onyomi_json) as string[],
      kunyomi: JSON.parse(r.kunyomi_json) as string[],
      strokeCount: r.stroke_count,
      meaningRu: r.meaning_ru,
    };
  }

  listKanji(level: LevelCode): KanjiPoint[] {
    return this.all<{
      id: string; level: string; char: string;
      onyomi_json: string; kunyomi_json: string; meaning_ru: string; stroke_count: number;
    }>('SELECT * FROM kanji_points WHERE level = ? ORDER BY id', [level]).map((r) => this.rowToKanji(r));
  }

  getKanji(id: string): KanjiPoint | null {
    const rows = this.all<{
      id: string; level: string; char: string;
      onyomi_json: string; kunyomi_json: string; meaning_ru: string; stroke_count: number;
    }>('SELECT * FROM kanji_points WHERE id = ?', [id]);
    return rows[0] ? this.rowToKanji(rows[0]) : null;
  }

  searchKanji(query: string): KanjiPoint[] {
    const q = query.trim().toLowerCase();
    if (!q) return [];
    return this.all<{
      id: string; level: string; char: string;
      onyomi_json: string; kunyomi_json: string; meaning_ru: string; stroke_count: number;
    }>('SELECT * FROM kanji_points ORDER BY level, id')
      .map((r) => this.rowToKanji(r))
      .filter(
        (k) =>
          k.char.includes(q) ||
          k.meaningRu.toLowerCase().includes(q) ||
          k.onyomi.some((r2) => r2.toLowerCase().includes(q)) ||
          k.kunyomi.some((r2) => r2.toLowerCase().includes(q)),
      );
  }
```
