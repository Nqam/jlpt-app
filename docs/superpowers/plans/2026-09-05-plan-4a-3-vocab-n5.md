# Plan 4a-3 — Vocabulary Reference (N5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new content category — vocabulary (слова) — starting with N5: 681 hand-translated word entries (headword, reading, part of speech, Russian meaning), a `vocab_points` table, a build-pipeline module mirroring `kanji.ts`, `ContentDb` read methods, and `VocabListScreen`/`VocabDetailScreen` replacing the `/vocab` placeholder.

**Architecture:** Mirrors the kanji pipeline (Plan 4a-1/4a-2) exactly: one TSV file per level in `content/vocab/`, parsed by a new `scripts/build-content/vocab.ts` (parallel to `kanji.ts`, not a shared module — matches the existing per-content-type file separation), merged into `content.db` via `write-db.ts`, read through new `ContentDb` methods, rendered by new screens. `id` is **computed in code from `headword`+`reading`**, not stored as a TSV column (keeps the file human-editable, avoids drift) — with a twist kanji didn't need: **duplicate-id fallback**. Four kana-only N5 words have two distinct dictionary senses sharing the same headword and reading (かける, キロ, もう, よく) — `parseVocabSeedFile` must detect a same-file id collision and append `-2`, `-3`, ... in file order, deterministically.

**Tech Stack:** Unchanged — TypeScript, `sql.js`, React 18, react-router-dom, Vitest, Playwright. No new dependency.

**Spec:** `docs/superpowers/specs/2026-09-04-plan-4a-kanji-vocab-content-design.md` §4/§5/§6 (vocab_points schema, pipeline, UI) — **descoped** per the already-settled decisions recorded in `docs/superpowers/specs/2026-09-05-vocab-n5-wip/STATUS.md` (no JMdict import, no `vocab_examples`/`vocab_kanji` tables, no furigana-example authoring in this plan). Those decisions are final; do not re-litigate them here.

**Predecessor:** Plans 4a-1 (`2026-09-04-plan-4a-1-kanji-n5.md`) and 4a-2 (`2026-09-05-plan-4a-2-kanji-n4.md`). Their Global Constraints (browser-safe `src/**`, offline/deterministic `content.db` build, TDD, commit format, Node-not-on-PATH prefix) apply unchanged here.

**Data provenance:** `content/vocab/n5.tsv`'s 681 rows come from `en.wikibooks.org/wiki/JLPT_Guide/JLPT_N5_Vocabulary` (CC BY-SA 3.0), parsed via the WIP directory's `parse_vocab2.py` into `vocab_n5_final.json`, then translated to Russian across five `ru_batch{1..5}.py` files (all 681 `num` keys verified present, zero dupes/gaps against `vocab_n5_final.json`) and merged into the TSV using `kanji_clean || reading_clean` as headword (not the JSON's raw `headword` field, which keeps an unwanted parenthetical usage-note for 28 entries — see Task 1 below for why this matters).

## Global Constraints

- **TSV format:** 4 tab-separated fields per line, real TAB characters: `headword\treading\tpos\tmeaning_ru`. Empty `pos` is valid (93 entries have no POS marked in the Wikibooks source). Blank lines and `#`-comment lines are skipped, mirroring `kanji.ts`.
- **`id` scheme:** `n5-{headword}-{reading}` when `headword !== reading`, else `n5-{reading}` (kana-only word) — computed in `parseVocabSeedFile`, not stored in the TSV. On an in-file collision (same computed base id appears twice), append `-2` for the second occurrence, `-3` for a third, etc., **in file order** — deterministic because `content/vocab/n5.tsv`'s row order is fixed. Exactly 4 real N5 collisions exist (かける, キロ, もう, よく — 2 senses each, no kanji form) — verified during data prep, listed in the Global Constraints so a future contributor doesn't mistake the `-2` suffix for a bug.
- **`levels.yml` needs no change.** N5's `status` is already `available` (flipped by kanji N5 landing in Plan 4a-1) and `status` is a per-level, not per-category, flag — vocab N5 content simply becomes reachable under the already-available N5 level.
- **`src/ui/components/LevelBadge.tsx` needs no change** — already generic (`{ level: LevelCode }`), reused as-is.
- **`src/ui/components/Nav.tsx` needs no change** — already has a `/vocab` → «Слова» nav entry; only the routed screen (currently `PlaceholderScreen`) changes.
- **UI layout: list, not grid.** Unlike kanji (single-character grid tiles), vocab entries are word-length text — mirror `GrammarListScreen`'s `<ul className="grammar-list">` list layout, not `KanjiListScreen`'s grid, for readability at 681 rows.
- **Baseline: Vitest 156, Playwright e2e 14** (Plan 4a-2's final state) — no regressions.

import { readFileSync, readdirSync } from 'node:fs';
import { join } from 'node:path';

const FIELD_COUNT = 4;

export interface VocabPoint {
  id: string;
  level: string;
  headword: string;
  reading: string;
  pos: string;
  meaningRu: string;
}

/**
 * Один уровень — один TSV-файл content/vocab/{level}.tsv. Строка:
 * headword<TAB>reading<TAB>pos<TAB>русское значение
 * Пустые строки и строки, начинающиеся с "#", пропускаются. `id` не хранится в
 * файле — вычисляется здесь из headword+reading, с дедупликацией `-2`/`-3` для
 * редких слов без кандзи, у которых два разных значения делят headword и reading
 * (см. Global Constraints плана 4a-3: かける, キロ, もう, よく).
 */
export function parseVocabSeedFile(path: string, level: string): VocabPoint[] {
  const out: VocabPoint[] = [];
  const seenIds = new Map<string, number>();
  const lines = readFileSync(path, 'utf8').split('\n');
  lines.forEach((raw, i) => {
    const line = raw.trim();
    if (!line || line.startsWith('#')) return;
    const fields = line.split('\t');
    if (fields.length !== FIELD_COUNT) {
      throw new Error(
        `${path}:${i + 1}: expected ${FIELD_COUNT} tab-separated fields, got ${fields.length}`,
      );
    }
    const [headword, reading, pos, meaningRu] = fields as [string, string, string, string];
    const baseId =
      headword === reading ? `${level.toLowerCase()}-${reading}` : `${level.toLowerCase()}-${headword}-${reading}`;
    const n = (seenIds.get(baseId) ?? 0) + 1;
    seenIds.set(baseId, n);
    const id = n === 1 ? baseId : `${baseId}-${n}`;
    out.push({ id, level, headword, reading, pos, meaningRu: meaningRu.trim() });
  });
  return out;
}

export function loadAllVocab(dir: string): VocabPoint[] {
  let files: string[];
  try {
    files = readdirSync(dir).filter((f) => f.endsWith('.tsv'));
  } catch {
    return [];
  }
  const out: VocabPoint[] = [];
  for (const file of files) {
    const level = file.replace(/\.tsv$/, '').toUpperCase();
    out.push(...parseVocabSeedFile(join(dir, file), level));
  }
  return out;
}

export function validateVocab(points: VocabPoint[]): string[] {
  const errors: string[] = [];
  const seen = new Set<string>();
  for (const p of points) {
    if (seen.has(p.id)) errors.push(`duplicate vocab id "${p.id}"`);
    seen.add(p.id);
    if (!p.headword) errors.push(`${p.id}: empty headword`);
    if (!p.reading) errors.push(`${p.id}: empty reading`);
    if (!p.meaningRu.trim()) errors.push(`${p.id}: empty meaningRu`);
  }
  return errors;
}

  private rowToVocab(r: VocabRow): VocabPoint {
    return {
      id: r.id,
      level: r.level,
      headword: r.headword,
      reading: r.reading,
      pos: r.pos,
      meaningRu: r.meaning_ru,
    };
  }

  listVocab(level: LevelCode): VocabPoint[] {
    return this.all<VocabRow>('SELECT * FROM vocab_points WHERE level = ? ORDER BY id', [level]).map((r) =>
      this.rowToVocab(r),
    );
  }

  getVocab(id: string): VocabPoint | null {
    const rows = this.all<VocabRow>('SELECT * FROM vocab_points WHERE id = ?', [id]);
    return rows[0] ? this.rowToVocab(rows[0]) : null;
  }

  searchVocab(query: string): VocabPoint[] {
    // SQLite's lower() is ASCII-only — filter in JS, same pattern as searchKanji/searchGrammar.
    const q = query.trim().toLowerCase();
    if (!q) return [];
    return this.all<VocabRow>('SELECT * FROM vocab_points ORDER BY level, id')
      .map((r) => this.rowToVocab(r))
      .filter(
        (v) =>
          v.headword.toLowerCase().includes(q) ||
          v.reading.toLowerCase().includes(q) ||
          v.meaningRu.toLowerCase().includes(q),
      );
  }
