# Дизайн: кроссплатформенное приложение (ПК + Android) для изучения японского по программе JLPT

- **Дата:** 2026-09-03
- **Статус:** черновик на ревью
- **Автор:** проработано совместно с пользователем (уровень N5)

## 1. Цель и рамки

### Что строим

Приложение для системного изучения японского языка по программе JLPT, работающее на
**ПК (Windows)** и на **Android-смартфоне** из одной кодовой базы. Приложение даёт
грамматические объяснения и комментарии, учит кандзи, слова и работе с текстами,
проводит тестирования и ведёт пользователя по уровням JLPT с наглядными шкалами
прогресса.

Единый веб-стек (React + TypeScript). Оболочка: Electron на ПК, Capacitor на Android.
Учебная логика и экраны — общие; платформенно-зависимы только доступ к файловой
системе, TTS и сборка.

### Целевой пользователь

Один пользователь, текущий уровень N5, родной язык — русский, читает по-английски на
базовом уровне. Учится самостоятельно, без преподавателя.

### Рамки версии 1

- Платформы: **Windows x64** (установщик NSIS) и **Android** (подписанный APK для
  ручной установки, без Google Play).
- Полностью поддерживаются уровни **N5 и N4** (грамматика, кандзи, слова, тексты, тесты).
- Уровни **N3–N2–N1** присутствуют в модели данных и интерфейсе как «скоро»;
  подключаются добавлением контента без изменений кода (кроме, возможно, новых типов
  вопросов на N1).
- Работа офлайн. Интернет используется только опционально и только по явному действию
  пользователя (подгрузка дополнительных примеров и словарных статей).

### Явно вне рамок v1

- Публикация в Google Play и App Store; iOS-версия.
- Синхронизация прогресса между ПК и телефоном (каждое устройство — свой `user.db`;
  перенос только ручным экспортом/импортом файла).
- Автообновление приложения (задел на будущее, в v1 — ручная переустановка).
- Пользовательская правка/создание карточек.
- Полная диагностика по навыкам (в v1 только быстрый адаптивный тест уровня).

## 3. Архитектура

### Общий принцип

Одна кодовая база. ~90 % кода (учебная логика, экраны, стили) платформенно-независимы
и живут в веб-слое. Платформенные различия спрятаны за узким интерфейсом
**`PlatformAdapter`** (см. ниже) — две реализации, десктопная и мобильная.

### Слои

- **Ядро (`src/core/`)** — чистый TypeScript, без DOM и платформенных API: `srs-engine`,
  `session-builder`, `quiz-engine`, `placement`, расчёт прогресса. Полностью
  юнит-тестируется.
- **Хранилище (`src/storage/`)** — `sql.js` (WASM) грузит `content.db` и `user.db` в
  память; запись `user.db` идёт через `PlatformAdapter.writeFile` с дебаунсом 500 мс.
- **UI (`src/ui/`)** — React + Vite, общие экраны и компоненты; адаптивная вёрстка (см.
  раздел 7).
- **Оболочка ПК (`shells/electron/`)** — главный процесс Electron: окно, `fs`, сетевые
  запросы, меню. Реализует `PlatformAdapter` через IPC.
- **Оболочка Android (`shells/android/`)** — Capacitor-проект: WebView, плагины
  Filesystem / TextToSpeech / App. Реализует `PlatformAdapter` через вызовы плагинов.

### `PlatformAdapter` (интерфейс)

```ts
interface PlatformAdapter {
  readonly platform: 'desktop' | 'android';
  // чтение поставляемого content.db (ресурс приложения) как байтов
  readBundledContentDb(): Promise<Uint8Array>;
  // user.db в приватном хранилище приложения
  readUserDb(): Promise<Uint8Array | null>;
  writeUserDb(bytes: Uint8Array): Promise<void>;
  // экспорт/импорт бэкапа user.db в доступное пользователю место
  exportUserDb(bytes: Uint8Array, suggestedName: string): Promise<void>;
  pickUserDbForImport(): Promise<Uint8Array | null>;
  // озвучка японского текста; no-op, если TTS недоступен
  speakJa(text: string): Promise<void>;
  ttsAvailable(): Promise<boolean>;
  // опциональные сетевые запросы (Tatoeba и т.п.)
  fetchJson(url: string, timeoutMs: number): Promise<unknown>;
}
```

Ядро и UI зависят только от этого интерфейса. Добавление iOS в будущем = третья
реализация адаптера, без изменений ядра.

### Две раздельные базы

### Две раздельные базы

- **`content.db`** — учебный контент (грамматика, кандзи, слова, тексты, примеры,
  списки уровней). Поставляется вместе с приложением, доступен только для чтения,
  обновляется вместе с версией приложения.
- **`user.db`** — состояние пользователя: карточки FSRS, прогресс уровней, история
  сессий, настройки, результаты тестов. Лежит в приватном хранилище приложения (на ПК —
  `app.getPath('userData')`, на Android — `Directory.Data`), **не затрагивается** при
  обновлении/переустановке приложения тем же ключом подписи. Имеет собственную схему с
  версией и миграциями.

Разделение гарантирует: обновление контента никогда не теряет прогресс. У ПК и телефона
свои независимые `user.db`; перенос — ручным экспортом/импортом.

### Модули

Каждый модуль — отдельная зона ответственности, тестируется независимо, общается через
явный интерфейс.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `content-db` | Доступ только для чтения к учебному контенту | `content.db` |
| `progress-store` | Чтение/запись состояния пользователя, расчёт прогресса и разблокировок | `user.db` |
| `srs-engine` | FSRS: очередь на сегодня, пересчёт интервала после ответа | `ts-fsrs`, `progress-store` |
| `session-builder` | Сборка ежедневного испытания и учебных сессий | `srs-engine`, `content-db`, `progress-store` |
| `placement` | Адаптивный вступительный тест → стартовый уровень и стартовые статусы | `content-db`, `quiz-engine` |
| `quiz-engine` | Генерация вопросов и дистракторов из контента; реестр типов вопросов | `content-db` |
| `ui` | Экраны, адаптивная навигация, темы, горячие клавиши (ПК) / жесты (Android) | всё выше напрямую (единый процесс) + `PlatformAdapter` |
| `platform` | Две реализации `PlatformAdapter` (desktop, android) | Electron IPC / Capacitor-плагины |

### Расширяемость по уровням

- Уровень — это строка в таблице `levels` базы `content.db`, а не константа в коде.
- Интерфейс (лента уровней, экраны справочников, полоски прогресса) строится
  динамически из списка уровней.
- Добавление уровня N3: положить файлы контента (`content/grammar/n3/*.md`, списки
  кандзи/слов), запустить сборку контента, выпустить обновление приложения. `user.db`
  не трогается; у пользователя появляется новый сегмент на ленте.
- Пайплайн сборки контента и его тесты параметризованы списком уровней.
- `quiz-engine` содержит реестр типов вопросов — новый тип (например, длинное чтение
  для N1) добавляется регистрацией, без правок существующих.

### Источники

| Данные | Источник | Лицензия |
|---|---|---|
| Слова, чтения, английский перевод | JMdict / JMdict_e (EDRDG) | CC BY-SA |
| Кандзи: чтения, значения, число черт, класс, частотность | KANJIDIC2 (EDRDG) | CC BY-SA |
| Порядок и анимация черт | KanjiVG | CC BY-SA |
| Примеры предложений с переводом | Tatoeba | CC BY 2.0 FR |
| Списки JLPT по уровням (отнесение кандзи/слов/грамматики к уровню) | Открытые списки (Tanos / Jonathan Waller и сверка с другими открытыми списками) | свободное распространение |
| Объяснения грамматики N5–N4 | Поиск в открытых источниках; недостающее автор пишет сам | своё / открытое |
| Русские переводы ядра слов N5–N4 (~1500) | Автор пишет на основе английских | своё |

Тексты для раздела «Тексты» на v1 составляются из уже знакомой пользователю лексики
и грамматики уровня (генерируются/курируются автором) либо берутся из открытых
источников с подходящей лицензией.

### Курируемый слой грамматики

Файлы в репозитории: `content/grammar/<level>/<id>.md`, человекочитаемые, проходят
ревью как код. Формат одного пункта:

```markdown
---
id: n5-wa-particle
level: N5
title: は (тема предложения)
tags: [частицы, базовое]
related: [n5-ga-particle, n5-mo-particle]
layer: 1
---

## Кратко
Одно-два предложения: что это и когда используется.

## Образование
Схема построения с обозначением частей речи.

## Нюансы
Смысловые оттенки, отличия от близких конструкций.

## Примеры
- 私（わたし）は学生（がくせい）です。 — Я студент.
- （ещё минимум два примера）

## Частые ошибки
Типичные ошибки русскоязычных и как их избежать.
```

### Сборочный шаг

`npm run build-content` — запускает **разработчик**, не конечный пользователь:

1. Скачать исходные данные (JMdict XML, KANJIDIC2, KanjiVG, дампы Tatoeba).
2. Распарсить, отфильтровать по уровням из списка сборки (v1: N5, N4).
3. Свести в нормализованную схему, проставить связи: слово ↔ кандзи, грамматика ↔
   примеры, кандзи ↔ слова.
4. Подмешать курируемый слой (объяснения грамматики, русские переводы ядра слов).
5. Записать `content.db`, положить в ресурсы приложения.

### Тесты пайплайна

- Схема `content.db` валидна.
- Каждый пункт грамматики уровня присутствует и имеет ≥ 3 примера.
- Все ссылки `related` указывают на существующие id.
- Каждое слово ядра уровня имеет русский перевод.
- Сборка идемпотентна (повторный запуск даёт тот же результат).
- Счётчики на выходе (сколько слов, кандзи, пунктов грамматики) — в ожидаемых
  диапазонах.

## 5. Цикл обучения

### Карточка

Единица повторения. Три типа: `grammar`, `kanji`, `vocab`. Для каждой в `user.db`
хранится состояние FSRS: стабильность, сложность, дата следующего показа, история
оценок.

### FSRS

- Библиотека `ts-fsrs` (MIT).
- После каждого ответа оценка `again / hard / good / easy` ставится **автоматически**
  на основе правильности ответа и времени реакции (пользователя не спрашивают вручную —
  меньше трения по гайдлайнам обучающих приложений).
- Движок пересчитывает интервал и записывает дату следующего показа.
- Параметры FSRS — по умолчанию; после накопления ~200 повторений возможна фоновая
  автоподстройка под пользователя (опция).

### Ввод нового материала

- Внутри уровня материал разбит на **слои**. Слой = согласованный набор грамматики,
  кандзи и слов примерно одной сложности. Следующий слой открывается по мере
  закрепления предыдущего.
- Дневная норма нового материала настраивается. По умолчанию: 5 пунктов грамматики,
  10 кандзи, 15 слов.
- Новый материал **не выдаётся**, пока очередь повторений превышает порог (защита от
  снежного кома).

### Ежедневное испытание

Экран «Сегодня» собирает `session-builder`:

1. **Повторения** — все карточки с наступившей датой. Верхний предел (по умолчанию
   100/день); остаток переносится на завтра.
2. **Новое** — порция нового материала по норме (если очередь повторений позволяет).
3. **Мини-тест дня** — 5–8 смешанных вопросов из уже выученного материала. Прямо на
   FSRS не влияет, но проваленные пункты возвращаются в очередь повторений.
4. **Стрик** — счётчик дней подряд. День засчитан, когда закрыты все повторения и
   пройдено новое (или новое на сегодня отсутствует).

### Учебная сессия нового пункта

Например, новый пункт грамматики:

Объяснение (Markdown из `content-db`) → примеры → 3–4 проверочных вопроса → карточка
заводится в FSRS.

### Типы вопросов (`quiz-engine`)

- выбор из 4 вариантов (значение / чтение / перевод);
- ввод чтения каной;
- сборка предложения из перемешанных слов;
- пропуск в предложении (грамматическая конструкция или частица);
- кандзи → слово и слово → кандзи;
- аудирование: озвучка примера через Web Speech API офлайн, если в системе есть
  японский голос; иначе тип вопроса пропускается.

Дистракторы (неправильные варианты) берутся из того же уровня и подбираются похожими
по чтению или смыслу — не случайные.

## 6. Прогрессия

### Статус карточки

Выводится из стабильности FSRS:

- `new` — ещё не вводилась;
- `learning` — введена, стабильность < 7 дней;
- `learned` — стабильность ≥ 7 дней;
- `mastered` — стабильность ≥ 30 дней.

### Прогресс внутри уровня

По каждой категории (грамматика / кандзи / слова) — две метрики:

- **Изучено** = доля пунктов категории в статусе `learning` + `learned` + `mastered`.
- **Закреплено** = доля пунктов в статусе `learned` + `mastered`.

Общий прогресс уровня = среднее «Закреплено» по трём категориям, взвешенное по числу
пунктов в каждой категории.

### Прогресс между уровнями

Горизонтальная лента: N5 → N4 → N3 → N2 → N1. Заполнение сегмента уровня = его общий
прогресс. N3–N1 показаны как «скоро» (контента пока нет).

### Разблокировка следующего уровня

- Следующий уровень открывается автоматически, когда «Закреплено» ≥ 60 % по **каждой**
  категории текущего уровня.
- Можно открыть вручную кнопкой «Я готов» с предупреждением.
- Уровни не запираются жёстко: можно параллельно закреплять текущий повторениями и
  начинать следующий.

### Экран прогресса показывает

- ленту уровней;
- три полоски («Изучено» / «Закреплено») текущего уровня;
- прогноз: «при текущем темпе уровень будет закреплён примерно через N недель»;
- календарь-heatmap активности и текущий стрик;
- «слабые места» — пункты с низкой стабильностью и частыми ошибками, с быстрым входом
  в тренировку по ним.

### Вступительный тест

- Адаптивный: сложность следующего вопроса зависит от предыдущих ответов.
- ~15–20 вопросов вперемешку (грамматика / слова / кандзи), ~5 минут.
- На выходе: примерный уровень (N5 / N4 / …) и стартовая расстановка — пункты, которые
  пользователь явно уже знает, помечаются как минимум `learning`, чтобы не начинать с
  нуля.
- Запускается при первом старте; повторно — из настроек.

## 7. Экраны и UX

### Принципы

Основано на гайдлайнах обучающих языковых приложений:

- один основной экран-действие; минимум решений перед началом занятия;
- мгновенная обратная связь на каждый ответ;
- прогресс виден всегда;
- в упражнениях нет «стен текста»;
- интуитивная и приятная подача: спокойная палитра, крупная и читаемая японская
  типографика, ненавязчивые анимации, понятные иконки с подписями, единообразные
  паттерны взаимодействия во всех разделах;
- ничего лишнего, но каждый экран информативен.

### Экраны

1. **Сегодня** (главный) — крупная кнопка «Начать» и одна строка статуса: сколько
   повторений, сколько нового, состояние мини-теста, стрик.
2. **Сессия** — полноэкранный режим: один вопрос или карточка за раз, точки прогресса
   сверху. На ПК — горячие клавиши (1–4 для вариантов, Enter — подтвердить, Space —
   озвучка); на Android — крупные кнопки-варианты, свайп для «дальше», кнопка озвучки.
   После ответа — мгновенный разбор: верно/неверно, почему, ссылка «подробнее».
3. **Учить новое** — слои текущего уровня, что открыто и что закрыто; вход в учебную
   сессию нового пункта.
4. **Грамматика** — справочник: пункты по уровням, фильтр и поиск, статус каждого
   пункта. Открытый пункт: объяснение, примеры, связанные пункты, кнопка «в
   тренировку».
5. **Кандзи** — сетка кандзи уровня со статусом-цветом. Карточка кандзи: анимация
   черт (KanjiVG), чтения, слова с этим кандзи, мнемоника при наличии.
6. **Слова** — списки по уровню и теме, статус, фильтр «слабые». Карточка слова:
   чтение, перевод, примеры, разбор входящих кандзи.
7. **Тексты** — короткие тексты по уровню; тап по слову — всплывающий разбор; после
   текста — вопросы на понимание.
8. **Прогресс** — см. раздел 6.
9. **Вступительный тест** — первый старт и запуск из настроек.
10. **Настройки** — дневные нормы нового материала, предел повторений, звук, тема
    (светлая/тёмная), фуригана вкл/выкл, экспорт и импорт `user.db`.

### Оформление

Светлая и тёмная темы (на Android — следование системной теме). Японский текст —
Noto Sans JP, шрифт в комплекте (офлайн). Фуригана над кандзи включается и выключается.
Один акцентный цвет для действий. Анимации минимальные: переходы между экранами и
индикация «верно/неверно». Тач-цели ≥ 44 px, безопасные зоны (вырез, жест-бар Android).

### Навигация (адаптивная)

Одни и те же экраны, раскладка по ширине области:

- **Широкий экран (ПК, планшет)** — боковая панель слева (иконки с подписями),
  «Сегодня» вверху.
- **Узкий экран (телефон)** — нижняя панель вкладок (5 основных: Сегодня, Учить,
  Грамматика, Кандзи/Слова, Прогресс), остальное — в «ещё». Заголовок экрана сверху.

Точка переключения раскладки — по ширине контейнера, не по платформе (планшет-Android в
альбомной ориентации получает боковую панель).

## 8. Тестирование и качество

### Подход

Разработка через тесты (TDD): тесты каждого модуля пишутся до реализации. Vitest — для
логики ядра и хранилища (не зависят от платформы, тестируются с фейковым
`PlatformAdapter` на Node `fs`). Playwright — пользовательские сценарии в Electron и в
браузере при мобильной ширине окна (эмуляция телефона). Реальный APK проверяется по
ручному чек-листу на устройстве/эмуляторе.

### Ключевые тесты по модулям

| Модуль | Тесты |
|---|---|
| `srs-engine` | интервал растёт после `good`, сокращается после `again`; карточка с наступившей датой попадает в очередь; предел очереди соблюдается |
| `session-builder` | новое не выдаётся при переполненной очереди; корректный состав ежедневного испытания; перенос остатка повторений |
| `placement` | адаптивный тест сходится; все ответы верны — верхняя оценка; смешанные ответы — средняя оценка |
| `quiz-engine` | дистракторы того же уровня, не совпадают с ответом; детерминизм при фиксированном seed |
| `progress-store` | пороги статусов; расчёт полосок «Изучено»/«Закреплено»; условие разблокировки уровня |
| `content-db` | валидность схемы, целостность связей, наличие всех пунктов уровня |
| `build-content` | идемпотентность; проверка лицензий источников; счётчики на выходе в ожидаемых диапазонах |

### Ручной чек-лист перед релизом

На обеих платформах: первый запуск → вступительный тест → полный день обучения →
закрытие и повторное открытие (прогресс на месте) → установка новой версии поверх
(`user.db` цел и мигрирован). На Android дополнительно: sideload-установка, разрешение
«неизвестные источники», предупреждение Play Protect, поворот экрана, работа в
самолётном режиме, TTS с системным японским голосом и без него.

## 9. Поставка

### ПК (Windows)

- `npm run build:desktop` → `electron-builder` → установщик NSIS для Windows x64 (ярлык,
  пункт в меню «Пуск»).

### Android

- `npm run build:android` → сборка веб-бандла → `npx cap sync android` → Gradle
  `assembleRelease` → APK, подписанный **постоянным keystore** (хранится в репозитории
  разработчика вне гита + резервная копия; тот же ключ для всех будущих версий, иначе
  установка поверх невозможна).
- Установка пользователем: скачать APK → разрешить установку из источника → тап →
  «установить всё равно» при предупреждении Play Protect.
- `minSdk` 26 (Android 8.0), `targetSdk` — актуальный на момент сборки.

### Общее

- Версии `app` и `content` — раздельные. При старте — миграция `user.db`, если её схема
  выросла.
- Резервные копии: автоэкспорт `user.db` раз в неделю (ПК — в `userData`, Android — в
  `Documents/JLPT`); ручной экспорт и импорт в настройках. Формат файла один и тот же —
  бэкап с телефона импортируется на ПК и наоборот (перенос прогресса между
  устройствами).
- Обновления: в v1 — кнопка «Проверить обновления» со ссылкой на страницу релиза,
  скачивание новой версии вручную. Автообновление — задел на будущее.
- Сетевые вызовы (Tatoeba API, расширенный словарь) — только по явному действию, с
  таймаутом и мягким запасным вариантом «нет сети — показываю локальные данные».

## 10. Открытые вопросы

- Конкретный набор и границы «слоёв» внутри N5 и N4 — определяется на этапе подготовки
  контента.
- Наличие японского TTS-голоса на устройстве пользователя — проверить; при отсутствии
  аудио-вопросы отключаются автоматически.
- Источник коротких текстов для раздела «Тексты» на N5–N4 — открытые материалы против
  составленных автором; уточняется при наполнении контента.
- Доступность Android-тулчейна (JDK 17, Android cmdline-tools, Gradle) в среде сборки —
  проверить до старта плана Android; при невозможности собрать APK локально план
  предоставляет полностью настроенный проект и точные команды сборки.
- Размер `content.db` в памяти на слабых телефонах — замерить после наполнения N5–N4;
  при необходимости включить ленивую загрузку таблиц примеров.
