# Дизайн: план 4d — Android-оболочка (Capacitor)

Дополняет общую дизайн-спеку (`2026-09-03-jlpt-desktop-app-design.md`, §8 «Оболочка
Android», §9 «Поставка → Android»). Уточняет конкретные технические решения на момент
реализации и фиксирует правки, согласованные с пользователем 2026-09-11 (брейншторм был
начат и остановлен 2026-09-08). TTS в общей спеке упомянут для Android — устарело: TTS
исключён из объёма приложения целиком (план 4c-1, 2026-09-05/06), в плане 4d TTS не
делается.

## 1. Оболочка и PlatformAdapter

`shells/android/` — Capacitor-проект (Gradle), `minSdk` 26, `targetSdk` — актуальный на
момент сборки. Новый `src/platform/android.ts` реализует существующий интерфейс
`PlatformAdapter` (`src/platform/adapter.ts`, 9 методов) через Capacitor-плагины —
ядро и UI не меняются, зависят только от интерфейса (как и было спроектировано).

Плагины: `@capacitor/core`, `@capacitor/android`, `@capacitor/cli` (dev),
`@capacitor/filesystem`, `@capacitor/share`, `@capacitor/browser`. TTS-плагин не
добавляется (см. выше).

## 2. Загрузка content.db и sql.js wasm — отличается от Electron

Electron грузит эти байты через IPC, потому что `file://`-протокол блокирует `fetch`
соседних файлов. Capacitor отдаёт веб-бандл через `https://localhost`
(WebViewAssetLoader) — статические файлы из Vite `public/` доступны обычным `fetch()`
без плагина.

Решение: `readBundledContentDb`/`readSqlWasm` в `android.ts` — `fetch('./content.db')`
/ `fetch('./sql-wasm.wasm')`, ответ → `Uint8Array`. Требуется новый шаг сборки: перед
`cap sync android` копировать `resources/content.db` (результат `build-content`) и
wasm-файл sql.js в `public/` только для android-сборки (не трогать Electron-путь через
`resources/`+`extraResources`).

## 3. user.db и бэкапы

- `readUserDb`/`writeUserDb`: `Filesystem` plugin, `Directory.Data`, файл `user.db` —
  приватное хранилище приложения, разрешений не требует.
- `autoBackupUserDb`: `Filesystem`, `Directory.Documents` (пространство приложения,
  не публичная папка), подпапка `JLPT/`, имя `backup-<YYYY-MM-DD>.db`, ротация —
  оставить `keep` самых свежих (та же сигнатура и семантика, что на десктопе).
- `exportUserDb`: записать байты в `Directory.Documents/JLPT/export-<date>.db`, затем
  `Share.share({ url })` — системный диалог «Поделиться» (Google Диск, файловый
  менеджер, почта и т.п.). Функциональный аналог десктопного `dialog.showSaveDialog`.
- `importUserDb`: **реализуется в v1 (правка исходного плана — было отложено на v1.1,
  пользователь запросил в v1)**. UI-элемент — обычный `<input type="file"
  accept=".db">` в `SettingsScreen` на android-варианте; Capacitor WebView открывает
  нативный файловый пикер без отдельного плагина. Выбранный файл читается через
  `File`/`FileReader` в браузерном JS → `Uint8Array`, дальше — та же валидация
  (`UserDb.validateImportBytes`), что и на десктопе. Пользователь открывает файл,
  который сам ранее сохранил через экспорт (см. выше) — Share-поток и import-поток
  совместимы (один и тот же файл user.db).

## 4. Навигация — drawer на телефоне

`src/ui/components/Nav.tsx`: сейчас два варианта (`sidebar` при ≥768px, `bottom` при
<768px) — 8 пунктов (7 + Настройки) в нижних табах становится тесно. Добавляется третий
вариант `data-variant="drawer"` для <768px: гамбургер-кнопка в хэдере + выезжающая
панель с теми же 8 пунктами (закрывается по выбору пункта или тапу вне панели). Сайдбар
на ПК (≥768px) не меняется. `bottom`-вариант выводится из кода — drawer его заменяет
полностью на всех узких экранах (не только Android; десктопное окно, сжатое до узкой
ширины, тоже получит drawer — тестируется тем же способом, что и раньше).

## 5. Подпись и сборка

- Постоянный keystore генерится один раз через `keytool`, хранится **вне git-репозитория**
  (например `C:\Users\am200\keystores\jlpt-app.jks`), пароль — в менеджере паролей
  пользователя. Тот же ключ используется для всех последующих версий (иначе установка
  поверх невозможна).
- В репозитории — только `android/keystore.properties.example` (шаблон с плейсхолдерами),
  реальный `android/keystore.properties` — в `.gitignore`.
- `package.json`: `build:android` → `build-content` → копия content.db+wasm в `public/`
  → `vite build` (веб-бандл) → `npx cap sync android` → `gradle assembleRelease`
  (подписанный APK через `keystore.properties`).
- Иконка/сплэш: сгенерировать через `@capacitor/assets` (`npx capacitor-assets
  generate`) из существующего квадратного исходника иконки (тот же источник, что
  использует `scripts/make-icon.ts` для .ico).
- Версии: `versionName` = `package.json` version (единая нумерация с десктопом,
  как и раньше — не бампать отдельно для Android), `versionCode` — монотонный счётчик,
  инкрементируется на каждую android-сборку независимо от `versionName`.
- Дистрибуция: APK прикладывается как ассет к тому же GitHub Release, что и `.exe`
  десктопа (один тег на версию). `checkForUpdate`/`GITHUB_REPO` уже платформо-
  агностичен — не меняется.

## 6. Тестирование

Эмулятор сознательно не используется (нет установленных system images, есть доступ к
реальному телефону для тестов).

- `android.ts` — юнит-тесты с моком Capacitor-плагинов (`Filesystem`/`Share`/`Browser`),
  зеркалит существующий паттерн `desktop.ts` (мок `jlmpBridge`).
- Drawer-нав и остальной UI — Playwright на узкой ширине в браузере, как и раньше;
  Capacitor-специфика (нативные плагины) в этих тестах не участвует, поэтому старый
  e2e-стенд не меняется в части рендеринга.
- Нативные пути, непроверяемые автоматически (Share-диалог, install/подпись, вырезы/
  жест-бар, поворот экрана, самолётный режим, установка через sideload и предупреждение
  Play Protect) — ручной чек-лист на реальном телефоне, часть финальной задачи плана.

## 7. Что НЕ входит в план 4d

- TTS (исключён из объёма приложения целиком, план 4c-1).
- iOS-адаптер (третья реализация `PlatformAdapter` — не в этом плане).
- Автообновление с загрузкой APK внутри приложения — только ссылка на релиз
  (как и на десктопе).
- Публикация в Google Play (только sideload APK, см. память проекта).
