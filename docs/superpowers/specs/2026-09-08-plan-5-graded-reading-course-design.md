# Дизайн: план 5 — погружающий курс градуированного чтения

Дата: 2026-09-08. Статус: согласовано.

## Проблема

Ежедневная сессия (повторения + N новых карточек в день + мини-тест) — это ~10 минут
и всё. Пользователь (N5, родной русский) хочет **погружающий курс**, который постепенно
ведёт через грамматику, кандзи и слова по мере нарастания сложности, с контентом
помимо теста. Отдельные карточки и справочники не складываются в связную картину;
новые карточки вводятся планировщиком «в вакууме», без контекста (это же — корень
жалоб на вступительный тест: варианты двусмысленны без предложения).

## Решение

Раздел «Тексты» перерастает в **курс уроков градуированного чтения**. Скелет курса —
последовательность текстов и диалогов нарастающей сложности. Грамматика и слова
вводятся **через контекст урока**: новые SRS-карточки рождаются не по «N в день», а
когда пользователь проходит урок, где этот пункт впервые встречается. Понимание
прочитанного — главная цель, интервальные повторения — поддержка.

Ключевые решения (все согласованы с пользователем на брейншторме 2026-09-08):

1. **Тип `Lesson`** — один текст **или** диалог + явные теги, что урок вводит/закрепляет.
2. **Сквозной порядок `stage`** (тоньше уровней N5/N4). Курс = уроки по `stage`.
   Добавление урока продлевает курс — код не трогается.
3. **Связь контента — вручную** во frontmatter (`introduces_grammar`, `introduces_vocab`,
   `introduces_kanji`, `reviews`). Сегментации японского в проекте нет, авторазбор
   ненадёжен; автор пишет текст и так — дописать список сознательно употреблённых id дёшево.
4. **Плеер урока — 5 линейных шагов**, прогресс сохраняется пошагово (можно бросить и
   вернуться): Новое → Чтение → Понимание → Закрепление → Итог.
5. **Карточки рождаются из уроков.** На финале урока каждый `introduces_*` id без
   карточки получает настоящую FSRS-карточку с оценкой 3 («Хорошо») — материал только
   что объяснён и проверён в контексте, место в статусе Learning.
6. **«N новых в день» убирается.** Планировщик больше не вводит карточки сам.
   Повторения (due) — без изменений. «Сегодня» = due-повторения + карточка
   «Продолжить курс».
7. **Вопросы шага «Закрепление» — из предложений самого урока.** Для грамматики cloze/
   assemble строится по предложению из тела урока, содержащему `{{g:id|…}}`. Контекст
   гарантирован по построению.
8. **Кандзи** — тот же принцип: карточка кандзи создаётся только когда урок его вводит
   (`introduces_kanji`). Справочник «Кандзи» остаётся для просмотра.

## Не входит

- **Озвучка / TTS** — исключена из проекта полностью (решение пользователя).
- **Сегментация японского / тап по любому слову** — вне объёма; тапаются только пункты,
  которые автор пометил inline-маркером.
- **Авто-пропуск урока по результатам вступительного теста** («ты уже знаешь всё, что
  этот урок вводит → урок засчитан») — отложено на v2.
- **Мини-тест** — остаётся как есть (grammar-only, ≥5 learned карточек), ортогонален.
- **Вступительный тест `/placement`** — остаётся как есть, план 5 его не трогает.
- **Android** — план 4d, отдельно.

## Декомпозиция на подпланы

Объём слишком велик для одного плана. Три независимо шипящихся подплана:

- **План 5-1 — модель контента + пайплайн + миграция.** Тип `Lesson`, схема content.db,
  парсер `lessons.ts`, inline-маркеры, миграция 15 текстов в уроки. Итог: content.db
  собирается с уроками, старые экраны текстов работают на новых данных без регресса.
- **План 5-2 — плеер урока.** `CourseScreen` (`/course`) + `LessonScreen` (`/lesson/:id`),
  5 шагов, персист прогресса, редиректы `/texts`. Итог: курс можно пройти, но карточки
  ещё не создаются, планировщик не меняется.
- **План 5-3 — связь с SRS.** Создание карточек на финале урока, удаление дрипа новых
  карточек из планировщика, карточка «Продолжить курс» на «Сегодня», починка затронутых
  тестов. Итог: полный цикл «чтение порождает карточки».

Каждый подплан → своя спека-уточнение (при необходимости) → план → реализация. Ниже —
общий дизайн; детализация под writing-plans идёт по подпланам, начиная с 5-1.

## 1. Модель контента (план 5-1)

### 1.1. Формат файла `content/lessons/*.md`

Формат — **надстройка над текущим `content/texts/*.md`** (та же структура секций
`## Текст` / `## Перевод` / `## Вопросы`, тот же `### Вопрос N` + `- [x]`/`- [ ]`
формат вопросов). Отличия: файлы плоско в `content/lessons/*.md` (без level-подпапок),
`level` заменён на `stage` + `kind` + теги.

```markdown
---
id: l-005-asa
stage: 5
kind: text            # text | dialogue
title: Моё утро
introduces_grammar: [n5-teiru, n5-kara-riyuu]
introduces_vocab: [n5-asa, n5-okiru, n5-hayai]
introduces_kanji: [n5-朝, n5-起]
reviews: [n5-wa, n5-wo]
---

## Текст

毎朝[まいあさ] {{g:n5-teiru|六時[ろくじ]に 起[お]きています}}。 {{v:n5-asa|朝[あさ]}}は
{{v:n5-hayai|早[はや]い}}ですから、コーヒーを 飲[の]みます。

学校[がっこう]まで バスで 行[い]きます。

## Перевод

Каждое утро встаю в шесть. Утром рано, поэтому пью кофе.

До школы еду на автобусе.

## Вопросы

### Вопрос 1

Во сколько встаёт автор?

- [x] В шесть
- [ ] В семь
- [ ] В восемь
```

- `kind: dialogue` — строки секции `## Текст` с префиксом говорящего: `A: おはよう。` /
  `B: おはようございます。` Префикс — `^[A-Za-zА-Яа-я]{1,8}:\s`. Перевод параллелен
  строкам через `\n\n`, столько же абзацев.
- Тело хранит фуригану в существующей нотации `кандзи[чтение]` (парсер `parseRuby` не
  меняется). Абзацы разделены `\n\n`.
- Валидатор проверяет паритет абзацев `## Текст` / `## Перевод` и (для `dialogue`)
  наличие префикса у каждой строки.

### 1.2. Inline-маркеры

`{{TYPE:id|видимый текст}}` где `TYPE ∈ v | g | k` (vocab / grammar / kanji).

- Только **первое вхождение** пункта за урок помечается автором.
- `id` обязан резолвиться в content.db (иначе сборка падает).
- Парсер извлекает: `(lesson_id, item_type, item_id, surface, sentence_ruby, sentence_ru)`,
  где `sentence_*` — предложение (до `。！？` или конца абзаца), содержащее маркер, в
  фуригана-нотации + его перевод (соответствующий абзац перевода, если однозначен;
  иначе пусто). `surface` = видимый текст маркера. Тело в БД хранится **с уже
  развёрнутым маркером** (`{{g:n5-teiru|六時に…}}` → `六時に…`), плюс параллельная
  таблица маркеров с позицией — рендер вешает тап-обработчик по совпадению `surface`.

### 1.3. Схема content.db (`scripts/build-content/schema.sql`)

Таблица `texts` / `text_questions` **переименовывается** в `lessons` / `lesson_questions`
(+ новые колонки/таблицы). `level` убирается (у уроков `stage`), `idx_texts_level` тоже.
Старый код читает через переименованные методы (см. §1.5). content.db не в git и
собирается заново — миграции схемы content.db не нужно.

```sql
CREATE TABLE lessons (
  id             TEXT PRIMARY KEY,
  stage          INTEGER NOT NULL,
  kind           TEXT    NOT NULL,           -- 'text' | 'dialogue'
  title          TEXT    NOT NULL,
  body_ruby      TEXT    NOT NULL,           -- маркеры развёрнуты
  translation_ru TEXT    NOT NULL
);
CREATE INDEX ix_lessons_stage ON lessons(stage);

CREATE TABLE lesson_questions (
  lesson_id    TEXT    NOT NULL,
  ord          INTEGER NOT NULL,
  prompt       TEXT    NOT NULL,
  choices_json TEXT    NOT NULL,
  answer_index INTEGER NOT NULL,
  PRIMARY KEY (lesson_id, ord)
);

CREATE TABLE lesson_introduces (
  lesson_id TEXT    NOT NULL,
  item_type TEXT    NOT NULL,                -- 'grammar' | 'kanji' | 'vocab'
  item_id   TEXT    NOT NULL,
  role      TEXT    NOT NULL,                -- 'introduce' | 'review'
  ord       INTEGER NOT NULL,
  PRIMARY KEY (lesson_id, item_type, item_id)
);

CREATE TABLE lesson_markers (
  lesson_id     TEXT    NOT NULL,
  item_type     TEXT    NOT NULL,
  item_id       TEXT    NOT NULL,
  surface       TEXT    NOT NULL,
  sentence_ruby TEXT    NOT NULL,
  sentence_ru   TEXT    NOT NULL,            -- может быть ''
  PRIMARY KEY (lesson_id, item_type, item_id)
);
```

### 1.4. Порядок / гейтинг курса

- **Порядок** — `lessons` по `(stage, id)`.
- **Обязательные уроки** — те, у кого `lesson_introduces` с `role='introduce'` непуст.
  Они образуют последовательный «хребет»: урок доступен, если предыдущий обязательный
  урок пройден. «Текущий» = первый непройденный обязательный.
- **Свободное чтение** — уроки с пустыми `introduces` (в т.ч. все 15 мигрированных
  текстов). Показаны в списке по своему `stage`, **не гейтят** прогресс, открыты как
  только их `stage ≤ stage текущего обязательного урока`. Помечены «чтение», не «урок».
- **Уровневые локи JLPT (правило 4g разблокировки N4 по 90%) на уроки курса НЕ
  распространяются** — курс гейтится только хребтом обязательных уроков и потолком
  `stage`; правило 4g управляет справочными разделами (грамматика/кандзи/слова), а не
  градуированным чтением.
- 15 текстов при миграции получают `kind: text`, `stage` (проставляется вручную в
  скрипте миграции, вперемешку с будущими уроками), пустые `introduces`.

### 1.5. `src/storage/content-db.ts`

- `listTexts`/`getText` → `listLessons(): LessonMeta[]` (id, stage, kind, title,
  introducesCount, isFreeReading), `getLesson(id): LessonFull | null`
  (+ `questions`, `introduces: {type,id,role}[]`, `markers`).
- `LessonFull` расширяет текущий `TextPoint` (тот же `bodyRuby`/`translationRu`/`questions`).
- `src/core/types.ts`: `TextPoint`/`TextQuestion` → `LessonMeta`/`LessonFull`/`LessonQuestion`
  (или новые типы рядом; `TextPoint` можно оставить алиасом на переходный период).

### 1.6. Пайплайн `scripts/build-content/lessons.ts`

- Зеркалит `parse-texts.ts`: gray-matter frontmatter + тело + `## Перевод` + `## Вопросы`.
- Дополнительно: парсит `{{TYPE:id|surface}}`, извлекает предложения-контексты, разворачивает
  маркеры в теле, собирает `lesson_introduces` из frontmatter.
- **Валидация** (жёсткая, сборка падает): каждый `introduces_*`/`reviews`/маркер id
  резолвится в соответствующей таблице; `stage` уникален или предупреждение при коллизии;
  паритет абзацев тело/перевод; у диалога каждая строка тела имеет префикс говорящего;
  `answer_index` в диапазоне.
- `index.ts`: `textsDir` → `lessonsDir: resolve(root, 'content/lessons')`.
- Скрипт миграции `scripts/build-content/migrate-texts-to-lessons.ts` (одноразовый,
  запускается вручную): читает `content/texts/*.md`, добавляет `stage`/`kind: text`,
  пишет в `content/lessons/`, печатает список. Потом `content/texts/` удаляется с диска.

### 1.7. Экраны на переходный период (план 5-1)

`TextsListScreen`/`TextDetailScreen` продолжают работать, читая уроки как тексты
(`listLessons`→фильтр, `getLesson`). Полноценный `CourseScreen`/`LessonScreen` — план 5-2.
Роуты `/texts`, `/texts/:id` живут до 5-2.

## 2. Плеер урока (план 5-2)

### 2.1. Роуты

- `/course` — `CourseScreen`: список уроков по `stage`. Каждый: «✓ пройден» /
  «● текущий» / «🔒 закрыт» / «чтение» (свободное). Кнопка на текущем — «Продолжить».
- `/lesson/:type` → нет; роут `/lesson/:id`, `<LessonScreen key={id} />` (обёртка как у
  `PlacementRoute` — remount при смене id).
- `/texts` → `<Navigate to="/course" replace />`; `/texts/:id` → `<Navigate to="/lesson/:id" replace />`.
- Nav: пункт «Тексты» 📖 → «Курс» 📖, `to="/course"`.

### 2.2. Шаги

`LessonScreen` — конечный автомат по шагам `0..4`, текущий шаг в
`course_progress[id].step` (см. §4). Кнопка «Назад к курсу» всегда.

0. **Новое.** Для каждого `introduces` (role introduce), по типам:
   - grammar → блок «Кратко» пункта (`sectionBody(bodyMarkdown, 'Кратко')`, read-only).
   - vocab → флеш-карточка: перед (`headword`) → тап «Показать» → (`reading` + `meaningRu`)
     → «Понятно» / «Ещё раз» (последнее возвращает карточку в конец очереди шага).
   - kanji → флеш-карточка: `char` → тап → `on`/`kun` + `meaningRu` → «Понятно» / «Ещё раз».
   Шаг пройден, когда все карточки отмечены «Понятно».
   Если `introduces` пуст (свободное чтение) — шаг 0 пропускается.
1. **Чтение.** Тело урока (`Furigana`), для `dialogue` — реплики бабблами по говорящему.
   Помеченные `surface` — тапаемый span → нижняя карточка (значение/чтение/«Кратко»).
   Кнопка «Показать перевод» разворачивает `translationRu` (как сейчас у текста).
2. **Понимание.** `questions` по одному: варианты, цветной + текстовый вердикт
   (`role="status"`), «Далее». Неверные ответы не блокируют — идём дальше.
3. **Закрепление.** 2-3 авто-вопроса по `introduces`-пунктам:
   - grammar с непустым `lesson_markers.sentence_ruby` → cloze/assemble по этому
     предложению (синтетический `GrammarPointFull` с `examples=[{jaRuby: sentence_ruby,
     ru: sentence_ru}]`, далее `genCloze`/`genAssemble` без изменений).
   - vocab → `genVocabMeaning`/`genVocabReading` + показ предложения-контекста над вопросом.
   - kanji → `genKanjiMeaning`/`genKanjiReading`.
   Автооценка та же (`grade`). Итог шага не влияет на FSRS напрямую (см. §3).
4. **Итог.** «Урок пройден». Создаются карточки (§3). `course_progress[id].done = true`.
   Кнопка «К курсу» / «Следующий урок».

### 2.3. Переиспользование

- Шаги 1-2 — почти текущий `TextDetailScreen` (тело + перевод + 4 вопроса + вердикт).
  Вынести общее в компоненты `LessonReader`, `ComprehensionQuiz`.
- Шаг 3 — `QuestionView` + `grade` (существуют).
- Флеш-карточка шага 0 — новый маленький компонент `FlashCard` (перед/зад/самооценка).

## 3. Связь с SRS (план 5-3)

### 3.1. Создание карточек на финале урока

`LessonScreen` шаг 4, эффект по «первый раз done»:

```
now = new Date(); params = fsrs-настройки из user (как в PlacementScreen)
for (const { item_type, item_id } of lesson.introduces where role='introduce'):
  if (user.getCard(item_type, item_id)) continue
  { card } = review(newCard(item_type, item_id, now), 3, now, 0, params)   // rating 3 "Хорошо"
  user.upsertCard(card)
user.setSetting('course_completed_ids', [...set, lesson.id])
```

- Оценка **3** (не 4 как у плейсмента): материал в статусе Learning, вернётся через
  ~10 мин / на следующий день — это правильно, его только что дали.
- `reviews`-пункты (role review) с уже существующей карточкой — ничего не делаем,
  всплывут сами.
- `insertReviewLog` **не** вызывается (не настоящая сессия повторения — как у плейсмента).

### 3.2. Удаление дрипа новых карточек из планировщика

`src/core/scheduler.ts`:
- `typeContext` больше не считает `unknownAvailable` / `introducedToday` для выдачи.
- `allocateBudget` и весь путь `newItems` удаляются из `split()`. `buildQueue` = только `due`.
- `DaySummary`: `newCount` всегда 0 (или поле удаляется; см. затронутые тесты).
- `daySummary`/`buildQueue`/`buildDailySession` сигнатуры не меняются.
- `availableItemIds` **остаётся** (нужен вступительному тесту — план 4h).
- `new_per_day` в настройках — удаляется из UI Настроек (поле мёртвое).

**Затронутые тесты (большой блast-radius, план 5-3 бюджетирует явно):**
`tests/core/scheduler.test.ts` (весь блок про новые карточки / water-fill),
`tests/core/session.test.ts` (learn-шаги), `tests/ui/TodayScreen.test.tsx`
(`newCount`), e2e `today.spec.ts` / `review.spec.ts` / `progress.spec.ts` /
`n4-unlocked.spec.ts` / `kanji-review.spec.ts` / `vocab-review.spec.ts` — все сидируют
новые карточки через дрип. Переводятся на сид готовых карточек (`writeSeededUserDb`
`learnedIds`/`dueIds` уже есть) или на прохождение урока.

### 3.3. «Сегодня»

`TodayScreen`:
- Строка = `{due} повторить · мини-тест {✓/—} · стрик {n}` (без «N новых»).
- Карточка **«Продолжить курс»** → `/lesson/{id текущего обязательного урока}`, если он
  есть. Подпись: «Урок {stage}: {title}». Если курс не начат — «Начать курс».
  Если все обязательные пройдены — «Курс пройден» + ссылка на свободное чтение.
- `daySummary` расширяется полем `nextLessonId: string | null` (или `TodayScreen` сам
  вычисляет через `content.listLessons()` + `course_completed_ids`).

### 3.4. Прогресс

`ProgressScreen` — без структурных изменений; добавить блок «Курс: пройдено X из Y уроков».
`levelCompletion` / разблокировка уровней — без изменений (считается по статусам карточек,
а карточки теперь копятся через уроки — механизм тот же).

## 4. Данные пользователя

Новый ключ настроек (без миграции схемы user.db — как `texts_read_ids`,
`placement_marked_*_ids`):

- `course_completed_ids: string[]` — id пройденных уроков.
- `course_progress: Record<lessonId, { step: number }>` — текущий шаг незавершённых
  уроков (для «продолжить с места»). Завершённый урок из этого объекта можно удалять.

`texts_read_ids` (старый) — мигрируется в `course_completed_ids` разовой идемпотентной
функцией `migrateTextsRead(user)` в `UserDbProvider` (рядом с `migratePlacementMarks`):
если `texts_read_ids` непуст и `course_completed_ids` пуст — скопировать, затем
`texts_read_ids` погасить (урок из плана 4h показал: миграцию надо делать одноразовой,
гася старый ключ).

`new_per_day` — остаётся в user.db как есть (не удаляем ключ), просто перестаёт влиять и
уходит из UI.
